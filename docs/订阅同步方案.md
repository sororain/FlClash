# 订阅链接与同步方案（最终版）

> 本文描述客户端订阅链接的拼装规则、订阅路径的生命周期、各入口的重试体系，
> 以及设计背后的取舍。对应代码：`lib/iqoo/services/subscription_service.dart`、
> `lib/providers/action.dart`（`syncSubscriptionNow` / `syncSubscriptionWithRetry`）、
> `lib/iqoo/app_lifecycle.dart`。

## 一、订阅链接的拼装（`subscription_service.dart`）

```
订阅 URL = OSS 竞速选出的 API 域名 + 后端返回的订阅路径（含 token）
```

- **域名**：`requestService.baseUrl`，即 OSS 竞速从候选列表里选出的可用地址，
  App 启动和登录页都会竞速刷新；
- **路径**：来自 `/user/getSubscribe` 响应的 `subscribe_url`，只取其 path + query 部分——
  它已按后台 `subscribe_path` 配置生成（留空即默认 `/api/v1/client/subscribe`，
  自定义时自动跟随）；
- **token**：与 `refreshTokenFromUserInfo` 同源，永远和本地凭证一致。

## 二、路径的生命周期

| 时点 | 动作 |
|---|---|
| 启动时 | `loadPersistedSubscribePath()` 从 SharedPreferences 恢复上次路径（排在 OSS 竞速之前） |
| 启动链路 / 登录后 | `refreshTokenFromUserInfo()` 请求接口，新路径与本地**对比，不一致才替换写入** |
| 运行期间 | 沿用内存中的值，不再变动 |
| 退出登录 | 随 token 一起从持久化中清除（`api_subscribe_path`），防串站 |
| 完全没有路径时 | `fetchSubscribeUrl` 返回 null，本轮同步跳过（**不拼默认路径兜底**，避免对自定义路径的站拼出 404） |

## 三、重试体系（按紧迫度分层）

> 设计原则：**重试的激进度与用户等待的紧迫度成正比**。

| 入口 | 策略 |
|---|---|
| 启动 / 登录后 / 支付成功（用户在等） | `syncSubscriptionWithRetry()`：最多 3 次、间隔 5 秒、一次成功（profile 就绪）即止 |
| 用户页「同步订阅」按钮（用户在盯） | 先 `refreshTokenFromUserInfo()` 刷新，再单次同步，失败如实提示 |
| 20 分钟定时同步（后台维护，没人在等） | 直接调 `syncSubscriptionNow()` 单次执行，失败靠周期自然重试，不轰炸用户通知 |

`syncSubscriptionWithRetry` 的每次尝试**先调 `refreshTokenFromUserInfo()` 刷新 Token 与路径**，
再执行同步——这保证「首次路径未就绪」的极端场景（路径为 null 静默跳过、不抛异常）
在重试中能够自愈，而不是三轮空转。

`syncSubscriptionNow` 自身还带一层**内嵌补救**：同步抛异常（链接失效 / Token 过期）时，
先 `refreshTokenFromUserInfo()` 刷新凭证，重拼链接后重试一次。

## 四、其他健壮性措施

- `refreshTokenFromUserInfo` 静默失败，不打断启动链路；
- 启动链路整体有 try-catch，任何一步网络故障不影响进首页，订阅同步和更新检查照常执行；
- token 持久化「先写盘再更新内存」，防中途崩溃导致状态不一致；
- 各入口（启动、登录、支付成功、用户页手动同步、定时任务）全部收口到统一的健壮链路。

## 五、核心思想

**域名信竞速、路径信后端、token 保新鲜、失败有重试**——每一环都有降级，
且不依赖后端做任何改动。
