## 一、整体架构对比

### 1.1 定时器机制

| 项目 | 0.8.93 | 当前项目 |
|------|--------|---------|
| 20 分钟定时 | `_autoUpdateProfilesTask()` | `_autoUpdateProfilesTask()` |
| 30 秒轮询 | ❌ 不存在 | ❌ 已删除（上游新增后删除） |

**结论：** 已一致。只保留 20 分钟定时器。

### 1.2 调用链路

**0.8.93:**
```
Timer(20min) → ref.read(profilesActionProvider.notifier).autoUpdateProfiles()
```

**当前项目：**
```

```

**结论：** 当前项目的 20 分钟定时器已改为调用 `syncSubscriptionNow()`（直接拉取订阅链接后更新），而非 0.8.93 的 `autoUpdateProfiles()`（遍历所有配置检查自动更新）。`autoUpdateProfiles()` 仅在应用初始化时调用一次。

### 1.3 自动更新逻辑

**0.8.93 (`lib/providers/action.dart:860`):**
```dart
Future<void> autoUpdateProfiles() async {
  for (final profile in ref.read(profilesProvider)) {
    if (!profile.autoUpdate) continue;

    try {
      await updateProfile(profile);
    } catch (e) {
      commonPrint.log(e.toString(), logLevel: LogLevel.warning);
    }
  }
}
```

**当前项目 (`lib/providers/action.dart:861`):**
```dart
// 代码完全一致
```

**结论：** 代码完全一致。

## 三、立即同步机制

| 触发时机 | 0.8.93 | 当前项目 |
|---------|--------|---------|
| 登录成功后 | ❌ 无 | ✅ `_autoSyncSubscribeOnStart()` → `syncSubscriptionNow()` |
| 购买成功后 | ❌ 无 | ✅ `_handlePaymentSuccess()` → `syncSubscriptionNow()` |
| OSS 地址切换后 | ❌ 无 | ✅ `_checkAndRefreshServerUrl()` → `_autoSyncSubscribeOnStart()` |
| **回到前台后** | ❌ 无 | ✅ `didChangeAppLifecycleState(resumed)` → `syncSubscriptionNow()` |

**当前项目多出的功能：** `syncSubscriptionNow()`（`lib/app_controller.dart:266`）

```dart
Future<void> syncSubscriptionNow() async {
  try {
    final url = await authService.fetchSubscribeUrl();
    if (url == null) return;
    final profile = _ref.read(currentProfileProvider);
    if (profile != null) {
      await updateProfile(profile.copyWith(url: url));
    } else {
      final newProfile = await Profile.normal(url: url).update();
      putProfile(newProfile);
      applyProfile(force: true);
    }
  } catch (e) {
    commonPrint.log('syncSubscriptionNow error: $e', logLevel: LogLevel.warning);
    globalState.showNotifier('订阅同步失败: $e');
  }
}
```

**购买成功后触发链路：**

```

    ├── showDialog("支付成功！")
    ├── appController.syncSubscriptionNow()    ← 后台立即同步
    └── await Future.delayed(1200ms)           ← 延迟返回
```

**登录成功后触发链路：**


**回到前台触发链路：**

## 四、OSS 服务器地址拉取

**当前项目独有功能**，0.8.93 不存在。

### 4.1 数据源

定义在 `lib/common/app_config.dart`：
```dart
static const oss = [
  'https://iqoo.oss-cn-shanghai.aliyuncs.com/sororain/base_url.txt',
];
```

OSS 文件内容为 base64 编码的 JSON，解码后格式：
```json
{ "urls": ["https://panel1.com", "https://panel2.com"] }
```

### 4.2 触发路径

| 触发时机 | 函数 | 位置 | 超时 |
|---------|------|------|------|
| **登录页加载** | `_fetchOssUrl()` | `lib/pages/login.dart:85` | OSS 下载 8s + 连通测试 5s |
| **已登录启动** | `_checkAndRefreshServerUrl()` | `lib/application.dart:116` | OSS 下载 8s + 连通测试 5s |

### 4.3 登录页 OSS 流程

```
登录页加载
    ↓
_fetchOssUrl()
    ├── 遍历 AppConfig.oss 列表
    │   └── GET 下载文件（8s 超时）
    │       └── base64 解码 → 解析 JSON → 拿到 urls
    │
    └── 遍历 urls，测试连通性（5s 超时）
        ├── 请求 /api/v1/guest/comm/config
        ├── 返回 200 → 自动填入服务器地址输入框 ✅
        └── 全不通 → 留空，用户手动输入
```

### 4.4 已登录启动 OSS 流程

```
启动 → _checkAuth() → 有登录态？
    ├── 否 → 跳过
    └── 是 → _checkAndRefreshServerUrl()
                ├── 当前地址可用 → 不动 ✅
                └── 不可用 → _fetchOssUrl() 获取新地址
                            → apiClient.configure(baseUrl: newUrl)
```

## 六、总结

| 对比项 | 状态 |
|--------|------|
| 20 分钟定时器 | ⚠️ 存在但调用链路不同（当前项目调 `syncSubscriptionNow()`，0.8.93 调 `autoUpdateProfiles()`） |
| `autoUpdateProfiles()` 逻辑 | ✅ 一致（当前项目仅在初始化时调用一次） |
| MD5 检测机制 | ✅ 完全一致 |
| MD5 文件分布 | ✅ 完全一致 |
| 30 秒轮询 | ✅ 已删除（与 0.8.93 一致） |
| 启动时立即同步 | ➕ 当前项目新增 |
| 购买后立即同步 | ➕ 当前项目新增 |
| 回到前台立即同步 | ➕ 当前项目新增（`lib/manager/app_manager.dart`） |
| OSS 服务器地址拉取 | ➕ 当前项目新增 |

**核心 MD5 机制已与 0.8.93 完全对齐。** 20 分钟定时器的调用目标不同（`syncSubscriptionNow` vs `autoUpdateProfiles`），但最终效果都是拉取订阅更新配置。当前项目多出的四个功能（启动时同步、购买后同步、回到前台同步、OSS 地址拉取）是增强特性。
