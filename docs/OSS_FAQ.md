# OSS 服务器地址获取 — 问答整理

> 本文档整理关于 OSS 获取服务器地址逻辑的常见问题与详细说明。

---

## Q1: OSS 支持多少个地址？

**支持任意数量。** `AppConfig.oss` 是一个列表，代码**遍历全部地址**，哪个先用哪个：

```dart
static const oss = [
  'https://oss1.example.com/path/base_url.txt',
  'https://oss2.example.com/path/base_url.txt',
  // 直接追加即可，不限数量
];
```

- 遍历顺序：列表顺序
- 找到可用的就 `break`，不再继续
- 全部不可用则跳过，不更新地址

---

## Q2: 支持手动输入原始服务器地址吗？

**支持。** OSS 只是自动发现机制，不是唯一途径：

| 场景 | 地址来源 | 说明 |
|------|---------|------|
| **登录页手动输入** | 用户输入框 | 用户可随时输入任意地址，优先级最高 |
| **登录页自动获取** | OSS 获取后填入输入框 | 仅当没有已保存地址时触发 |
| **登录后后台刷新** | OSS 获取后更新 apiClient | 仅当检测到当前地址不可用时触发 |

---

## Q3: OSS 检测逻辑是什么？

两层检测：

### 第一层：获取地址列表

```
遍历 AppConfig.oss
  │
  GET <oss_url>
  ├── 成功 → Base64 解码 → JSON 解析 → 提取 urls[]
  │         → break（只取第一个成功的 OSS）
  └── 失败 → 继续下一个 OSS 地址
```

### 第二层：连通性测试

```
遍历 urls[]
  │
  GET <url>/api/v1/guest/comm/config
  │
  ├── statusCode == 200 → 可用 ✅
  │      登录页: 填入 serverUrl 输入框
  │      后台: 更新 apiClient config
  │
  └── 抛异常 / 非 200 → 跳过，测下一个
      全部不可用 → 不更新，保留当前地址
```

## Q4: 8 秒超时是如何运作的？

**这是 Dio 的 `connectTimeout`，指建立 TCP 连接的超时时间，不是整个请求的时长。**

### 运作流程

```
发起 GET 请求
    │
    ├── 8 秒内连接建立成功
    │       └── 继续等待响应数据下载（无时间限制）
    │
    └── 超过 8 秒仍未建立连接
            └── DioException 抛出
                catch 捕获 → continue 下一个 OSS 地址
```

### 三个关键点

| 要点 | 说明 |
|------|------|
| **只管连接** | 不限制连接建立后的数据传输时间（OSS 文件小，通常几 KB） |
| **每个地址独立** | 第 1 个 8 秒超时 → 试第 2 个 8 秒，依次类推 |
| **不卡死** | 全部超时则跳过，用户可手动输入地址 |

---

## Q5: 整个流程有哪些超时？

| 层级 | 超时 | 说明 |
|------|------|------|
| OSS 文件获取 | **8 秒 connectTimeout** | 建立连接到 OSS 的超时 |
| 地址连通性测试 | **5 秒 connectTimeout** | 测试单个服务器是否可用 |
| 站点配置加载 | **10 秒 connectTimeout** | 获取站点标题/描述等信息 |

---

## Q6: 什么时候会触发 OSS 获取？

| 场景 | 调用位置 | 触发时机 |
|------|---------|---------|
| **登录页加载** | `login.dart:_fetchOssUrl()` | 打开登录页时，没有已保存地址则触发 |
| **登录后检查** | `application.dart:_checkAndRefreshServerUrl()` | 恢复会话成功后，检测到当前地址不可用时触发 |
